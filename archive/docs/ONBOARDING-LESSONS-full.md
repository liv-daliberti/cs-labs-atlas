# Onboarding lessons: the friction ledger

One row per lesson from onboarding Michigan (7th school, 2026-10-29), the University of Chicago (8th, 2026-11-02) and Georgia Tech (9th, 2026-11-03),
merged on 2026-11-05 (owner: "merge the mistakes learned from the process of Georgia Tech, U of M, and U Chicago") before Harvard, Johns Hopkins and WashU
start. The protocol that uses it is `docs/ADDING-A-SCHOOL.md` (v3). Sources: `hierarchy/{michigan,uchicago,gatech}/reports/` (`PROTOCOL-FRICTION.md`
rows are cited as UC n and GT n; Michigan's `REQUESTS-FOR-BUILDER.md` as MI n; `STAGE-*.md`), `docs/ROADMAP.md` #42-#51, `docs/RULES.md`, the git log.

**Status.** `fixed` = a code or config change with a test (commit or test named). `checked` = a gate or trap check added on `agent/protocol-v3`
(`tools/onboarding_traps.py`, `tools/stage_gate.py`) with a test in `tests/test_onboarding_traps.py`; the lesson cannot recur silently. `documented` =
a rule or procedure in the protocol or the rules, no code. `open` = not fixed; the ROADMAP row (#52-#56, added on this branch) or request says what is
left. Where a lesson is fixed in code **and** now has an early check, the status is `fixed+checked`.

Run every trap check at once with `atlas stage-gate <key> --traps`; each stage gate also runs the checks of its stage.
