# Reviewed missing titles

`paper-title-review.json` is an optional school-local reviewed input, routed by `atlas_paths.DATA_FILES`. It fills only a null, empty or whitespace-only title after normal identity, affiliation, appointment, type and edition grouping. It cannot lend a title to identity matching or create a new edition/alias group. Nonempty titles, including contradictory Dense/HMM metadata, are preserved.

Each review names the exact PI and OA/accepted collection-work selector plus DOI. Every supplied selector must agree. The complete native work must match one approved canonical JSON SHA256 preimage before enrichment; its exact original missing-title value and complete ordered source byline are included. The raw individual-record/page capture SHA256 is retained as reviewed source provenance. The builder verifies the canonical work preimage at runtime; it does not reopen mutable raw cache files or PDFs. Source review must physically validate those capture/PDF hashes before the input is accepted.

The proof includes a full parsed publisher PDF (hash, byte count, pages, literal title/byline/publication quotes) and an owned local official DBLP record (the accepted PI's PID, source-file hash, publication key, DOI, title, complete byline and year). Both must agree on the exact edition DOI, title and year. Missing/partial bylines, changed source objects, different years/editions, wrong DOI or competing exact candidates are held. Ordinary Unicode/apostrophe and DBLP disambiguation-label comparison does not rename output authors. A source spelling discrepancy needs an explicit publisher-hash-bound reviewed mapping. The eight TOC inputs preserve the source spelling `Johan Haastad`; the actual publisher spelling `Johan Håstad` is evidence, not an output correction.

The accepted edition pointer array also has a preimage hash. A new or unreviewed alias/edition group therefore holds the enrichment. Title-sensitive venue dating is checked without changing the date; enrichment is held if that would change the already accepted date. No source cache, original byline/date, identifier, scientific identity method, membership status or alias is changed.

After enrichment the ordinary `drop_not_papers` quality checks run again on filled rows. A newly exposed nonpaper title can remove that row; the original acceptance gates are never bypassed. The report records title-review input hash and per-row filled/held/nonempty outcomes, with quality passed/rejected; ordinary rejection counters/samples also apply. Quality-sensitive acceptance deltas require review before canonical promotion. Eight TOC proposals produce only title/provenance changes and no quality drops in the exact replay.

Output rows carry `titleEnrichment`; `report.json` carries `paperTitleReview`. The input is capped at5MB and contains curated bibliographic evidence/hashes, never raw API cache bodies or PDF bytes. Source variants belong in explicit preimage allowlists, not fuzzy matches or wildcards. Input files on an implementation branch remain proposals until independently reviewed and landed. No canonical package, catalog or registry is written by this change.

Regression coverage includes missing-only fills, exact existing edition aliases, source preimage drift, wrong/shared DOI, all-candidate conflicts, byline/year/edition/ownership gaps, identity holds, candidate-link preservation, unchanged nonempty metadata, late quality rejection, and all eight original TOC records across twelve exact native-shaped source variants. The NFS replay reads immutable scratch source bytes; it skips when that local packet is absent. Synthetic CI cases test the generic safety boundaries independently.
